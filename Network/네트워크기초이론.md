
## MAC 주소, IP 주소, Port 번호가 식별하는것
- MAC 주소는 NIC(Network Interface Card)에 대한 식별자
- IP 주소는 호스트에 대한 식별자
	- 호스트는 인터넷에 연결된 컴퓨터
	- 인터넷에 연결되었을 때만 호스트라고 부름
- Port 번호는 프로세스(Process)에 대한 식별자
	- 네트워크를 다루는 사람들은 Port번호를 서비스에 대한 식별자라 부르기도함
	- 서비스의 예시에는 HTTP, HTTPS등이 존재함. HTTP는 80, HTTPS는 443 고정


 NIC의 특징
 - 1개의 MAC를 가지고 n개의 IP 주소를 매핑(바인딩) 할 수 있음
 - MAC 주소는 변경이 가능함
 - 1개의 노트북에 유선/무선이 가능하면 2개의 NIC가 존재하고 2개의 MAC 주소를 가짐


## Host, Switch, Network의 관계들
- Host는 Compute + Network
- Network에는 Network 자체인 것들이 존재하고, Network를 이용하는 주체들이 존재합니다.
- Host(Compute + Network)가 **Network 자체를 이루는 컴퓨터라면 Switch**라고 부릅니다.
- **Network를 이용하는 주체를 엔드포인트(Endpoint)** 라고 부릅니다.
	- 엔드포인트를 우리말로 끝단, 단말이라고 정의함
- Network 이용 주체인 엔드포인트를 Peer, Server, Client 등이 존재함.
	- 네트워크에서 Host가 존재하는 역할에 따라서, 기능에 따라서 나눈다
- Network 자체인 Switch에 해당하는 것들은 **라우터(Router)**
	- 다른 것들로 방화벽(Firewall), IPS(칩입 방지 시스템, Intrusion Prevention System)
	- 방화벽과 IPS들을 보안 Switch라고 부른다.
	- 라우터는 길을 찾기 위한 용도로 Switching을 수행한다. 즉, 경로 선정입니다.
- Network에 해당하는 대표적인 것은 인터넷(Internet)이 존재합니다.
	- **인터넷(Internet)의 구성요소로 대표적으로 라우터와 DNS** 등으로 구성됨
- Mac Address는 L2에 속한다. 만약 MAC을 가지고 스위칭을 하게 되면 이 Switch를 L2 Switch라고 부른다.
- Router가 Switching 한다는 것은 무슨 의미?
	- 들어온 패킷의 목적지를 확인하고 내부적으로 적절한 인터페이스로 옮겨주는 물리적인 동작
- Switch가 IP 주소를 이용해서 스위칭하면 L3 Switch라고 부른다.
- Switch가 Port 번호를 이용해서 스위칭하면 L4 Swtich라고 부른다.
- Switch가 HTTP를 이용해서 스위칭하면 L7 Swtich라고 부른다.
- Switch의 비용은 L2로 갈수록 싸지고, L7으로 갈수록 비싸진다.
- Switch은 무엇을 가지고 스위칭하느냐가 중요함.
- 공유기도 Switch 역할을 수행함.
	- L2 Switch, 공유기는 각 기기의 MAC 주소를 기억하고, 적절한 포트로 데이터를 보내는 전형적인 L2 스위치 동작을 수행함
	- 공유기의 목적은 하나의 public IP를 여러 호스트가 공유해서 인터넷에 접속할 수 있게 하는 장치
	- 공유기에 연결된 호스트들 간에도 서로 통신이 가능한게 해준다. 그래서 공유기 내부에는 L2 스위치가 포함되어 있음.
	- 

 정리
 - Compute에 Network가 연결된 것을 Host라고 부른다.
 - Host는 크게 Network를 이용하는 주체와 Network 자체를 의미하는 Host가 존재한다.
 - Network를 이용하는 주체를 엔드포인트(Endpoint)라고 부르며, 엔드포인트는 역할에 따라서 종류를 구분하는데, 대표적으로 Peer, Server, Client가 존재합니다.
 - Network 자체를 이용하는 Host를 Switch라고 부른다.
 - Network에 대표적인 인터넷(Internet)은 라우터와 DNS로 구성됨
 - Switch가 MAC 주소를 가지고 Switching하면 L2 Switch
 - Switch가 IP 주소를 가지고 Switching하면 L3 Switch
 - Switch가 Port 번호를 가지고 Switing하면 L4 Switch
 - Switch가 HTTP를 가지고 Switing하면 L7 Switch
 - L3 Switch의 대표적인 것이 Router이다.

## Ipv4 주소 체계
- IP 주소는 Host에 대한 식별자
	- 예시를 들어 대한민국의 행정체계가 존재하고 대한민국에 개인이 존재한다. 이때 개인에게는 주민등록번호가 할당된다. IP 주소에 비유하면 개인에게 할당되는 개인 그 자체는 Host이고, 주민등록번호는 IP 주소에 해당하고, 대한민군 행정체계는 Network에 해당됩니다.
- IP(Internet Protocol)
- IP 주소는 IPv4, IPv6 2종류가 존재합니다. 두 종류의 차이점은 주소 길이입니다.
	- IPv4는 32bit
	- IPv6는 128bit
- IPv4 주소로 나올수 있는 IP주소는 2^32은 약 43억개정도가 됩니다.
	- 즉, 인터넷에 연결된 약 43억개의 Host가 존재함
- 예를 들어 IPv4 주소가 `192.168.60.14`라고 가정한다. 그러면 점(`.`)을 기준으로 각각의 자리에서 나올수 있는 숫자의 범위는 0~255입니다. 각 자리마다 8bit씩 할당되고 8bit로 표현할 수 있는 숫자의 개수는 2^8=256개이기 때문입니다.
	- 192라는 십진수 값을 이진수로 변환하면 `1100 0000`입니다. 16진수로 변환하면 `C0`입니다.
- IPv4 주소는 두가지로 쪼갤 수 있다.
	- 위 예시에서 `192.168.60.14`를 `192.168.60`을 **Network ID**라고 부르고, `14`를 **Host ID**라고 부른다.
- **IP 주소는 Network ID와 Host ID**로 나뉜다고 할 수 있다.
- IP주소가 존재하고 Network ID의 길이가 24라면 Host ID는 8이 된다.
- IP 주소에서 Network ID의 길이가 얼마인지 나타내는 것이 **Network-Mask**입니다.
- IPv4 주소 `192.168.60.14` 이고, Subnet-Mask가 `255.255.255.0`이다.
- Subnet-Mask의 주소값(`255.255.255.0`)을 16진수로 표현하면 `0xFF`이고 2진수로 표현하면 `1111 1111`입니다.
- 192(`1100 0000`)에 255(`1111 1111`)를 AND 연산 하면 `1100 0000`(십진수 192)가 된다.
- 그러나 14(`0000 1110`)에 0(`0000 0000`)을 AND 연산하면 `0000 0000`(십진수 0)가 된다.
- **`192.168.60.14`와 `255.255.255.0`을 bit AND연산하면 `192.168.60.0`이 나온다.**
- IPv4 주소와 Subnet-Mask와 연산하는 것이 귀찮기 때문에 `192.168.60.14/24`와 같이 표현한다. 이러한 표현을 **CIDR(Classless Inter-Domain Routing)**라고 합니다.
	- 이 의미는 HostID가 8bit이고, NetworkID가 24bit를 의미한다.

정리
- IP 주소는 NetworkID와 HostID로 나뉜다.
- IPv4 주소 기준 각각의 자리는 8bit가 할당되고 각각의 자리마다 0~255 사이의 수를 설정될 수 있음
- Subnet-Mask는 IP 주소에서 어디까지가 NetworkID이고 어디까지가 HostID인지 판별하는 가이드라인입니다.
	- 예시를 들어서 "042-1234-5678"과 같은 전화번호가 존재하면 042는 지역번호이고, 1234-5678은 개별번호가 됩니다. 이때 042까지가 지역번호인지를 판단하는 것이 서브넷 마스크의 역할입니다.
- 예를 들어 IPv4 주소가 `192.168.60.14`이고 Subnet-Mask 주소가 `255.255.255.0`이라면 Network ID는 `192.168.60`이고 HostID는 `14`입니다.
- `192.168.60.14/24`와 같이 표현하면 앞에 24bit(3자리)까지가 NetworkID이고 나머지 8bit(1자리)가 HostID라는 의미입니다.
	- 이는 `192.168.60` 주소를 가진 네트워크가 `192.168.60.1 ~ 192.168.60.254` 까지 254개의 기기를 수용할 수 있다는 의미입니다.
	- `192.168.168.0`은 Network 자체의 주소를 가리킴
	- `192.168.168.255`은 브로드캐스트(Broadcast Address)라고 해서 이 네트워크에 연결된 모든 기기에 데이터를 한번에 뿌릴때 사용합니다. (전체 공지사항)

## 개발자 입장에서 Port 번호 이해하기
- Port번호는 Process의 식별자 번호, Service 식별자 번호, Interface 식별자 번호라고 부를 수도 있다.
- User 모드의 애플리케이션(프로세스)이 커널(Kernel) 모드의 TCP에 접근하기 위한 인터페이스가 파일 형태로 제공되는데, 이때 이 파일을 프로토콜로 추상화 했기 때문에 파일이라고 안하고 소켓(Socket)이라고 합니다.
- **Socket에 첨부(Attach)되는 정보 중에 하나가 Port번호입니다.**
- TCP/IP Port 번호는 기본적으로 16bit 크기를 가진다.
	- 나올 수 있는 Port 번호는 2^16(65536)개이다.
	- Port 번호 범위 : `0 ~ 65535`
	- Port 번호 `0`과 `65535`는 사용할 수 없다. 실질적으로 2^16-2(65534)개 사용가능함.
		- 0번 포트는 네트워크 프로토콜에서 포트가 없거나(ICMP 등), 패키 헤더 손상, 특수 목적(시스템 예약)을 나타내는 사용되어 보안 및 기능상 제한됨
		- 65535번 포트는 오버플로우 및 오류 방지하기 위해서 사용하지 않는다. 일부 오래된 시스템이나 네트워크 장비에서는 이 최댓값을 처리할때 계산 오류가 발생할 가능성이 높기 때문
- 어떤 Host의 IP 주소가 `192.168.0.10`이라고 가정합니다.  그리고 프로세스 2개가 실행되었습니다. 하나는 엣지 브라우저, 다른 하나는 크롬 브라우저입니다. 
- 각각의 브라우저들은 인터넷과 연결하기 위해서 소켓을 열것입니다. (각각 1번소켓, 2번소켓이라고 가정함)
	- 엣지 브라우저 소켓에 연결되는 포트번호는 30000번이면 크롬 브라우저의 소켓의 포트번호는 30000번을 첨부할 수 없음. 다른 번호인 30001번같은 포트번호를 첨부해야함.
- 인터넷 연결을 하게 되면 패킷을 받게 되는데, 하드웨어의 NIC를 거치고, IP, TCP를 거쳐서 최종적으로 HTTP에 도달하게된다. 그런데 **패킷이 TCP에 도달하게 되면 어느 프로세스로 갈것인지 포트번호를 기준으로 결정한다.**

정리
- Port번호는 Process의 식별자이다.
- User 모드의 애플리케이션이 커널 모드의 TCP에 접근하기 위한 인터페이스가 파일 형태로 제공되는데, 이를 소켓이라고 부릅니다.
- 소켓에 첨부되는 정보 중에 하나가 Port번호이다.
- Port 번호는 16bit를 가지고 실질적으로 2^16 - 2개의 포트번호를 가질 수 있다. `0`과 `65535`는 설정할 수 없다.
- 패킷이 TCP에 도달하게 되면 어느 프로세스로 갈것인지를 Port 번호를 기준으로 결정하게 된다.

## Switch가 하는 일은 Switching이다
- Switching은 경로선택 입니다.
- Network를 고속도로에 비유할 수 있습니다.
- Switch는 교차로로 비유할 수 있고, Switching은 교차로에서 경로를 선택하는 것입니다.
- 최적의 경로가 A->D->목적지인데, 어떻게 하면 최적의 경로를 선택할 수 있는가?
- 인터넷은 라우터(Router)의 집합체다 라고 정의함
	- 라우터는 기본적으로 L3 Switch입니다. 즉, IP 주소를 가지고 스위칭을 함
- 고속도로에 비유하면 교차로는 라우터에 해당한다.
- 네트워크에서는 최적의 경로를 선택하기 위해서 라우터끼리 통신한다.
	- 라우터끼리 어떤 프로토콜을 가지고 서로 통신하며 최적의 경로 선택을 계산 및 선택한다.
- 고속도로 비유에 존재하는 자동차들은 하나의 패킷이라고 할 수 있다.
- 비유 정리
	- 고속도로 = Network
	- 교차로 = Router(Switch)
	- 경로 선택 = Switching
	- 자동차 = 패킷(Packet)
	- 목적지 = 수신 Host
	- 출발지 = 송신 Host
- 각각의 교차로에 존재하는 이정표를 **라우팅 테이블(Routing Table)**이라고 부를수 있다.
- 라우터들은 라우팅 테이블을 참고하여 경로 선택을 하게 된다.

정리
- Switch는 Router이다.
- 인터넷은 거대한 Router의 집합체이다.
- Router는 L3 Swtich이다.
- Switch는 교차로에 비유할 수 있고, Switching은 교차로에서 경로를 선택하는 것이다.
- 경로 선택의 근거가 되는 것은 이정표가 되는건데, 이 이정표를 라우팅 테이블이다.

## 네트워크 데이터 단위 정리
- User 모드의 해당하는 OSI 계층은 Socket 수준이다.
- 파일은 기본적으로 내용이 늘어날수록 길이가 늘어난다.
- User 모드의 프로세스가 커널 모드의 TCP에 접근하기 위해서는 파일 형태로 접근하는데, 이 파일을 소켓이라고 부른다.
- 소켓 파일에 사용하는 데이터 단위를 **스트림 데이터(Stream Data)**를 작성한다.
	- **Socket에 Stream 형태로 데이터를 작성한다.**
- 스트림 데이터는 언제 끝날지 모른다. 개발되는 프로그램에 따라서 다르다. 길이가 길어질수 있음.
- 스트림 데이터의 길이는 계속 길어져서 IP 레이어에서 다루는 길이보다 길어질 수 있다.
- TCP 레이어에서 다루는 데이터 단위를 세그먼트(Segment)라고 부른다.
- IP 레이어에서 다루는 데이터 단위를 패킷(Packet)라고 부른다.
- IP 레이어 밑의 레이어에서 다루는 데이터 단위를 프레임(Frame)라고 부른다.
- 소켓에 작성한 Stream 데이터를 TCP 레이어에 전달할때는 세그먼트 데이터 단위로 전송한다.
	- Stream 데이터를 분해한 다음에 세그먼트 데이터로 조립한다.
	- Stream 데이터를 일정 길이로 자른 다음에 세그먼트 데이터로 조립하는데, 이러한 길이의 최대 크기를 **MSS(최대 세그먼트 크기, Maximum Segment Size)**라고 부른다.
- 최대 세그먼트 크기(MSS) 값은 Packet의 최대 크기인 **MTU(Maximum Transfer Unit)** 에 따라서 결정된다.
- MTU는 특별한 이유가 없다면 1500byte가 됩니다.
	- 예를 들어 Socket Stream 데이터 사이즈가 1.5MB라면 패킷의 개수는 적어도 약 1000개 이상일것입니다.
- 패킷은 또 프레임(Frame) 데이터 단위로 분해 및 조립됩니다.

정리
- User 모드의 App의 프로세스 수준에서는 즉, 다른말로 소켓 수준에서는 Stream 데이터 단위로 작성된다.
- Stream 데이터는 최대 길이를 알수 없는 끝없는 데이터입니다.
- Stream 데이터를 네트워크로 전송하기 위해서는 TCP 레이어의 데이터 단위인 세그먼트 데이터 단위로 분해가 일어나고 세그먼트 데이터로 조립됩니다.
- 세그먼트 데이터 단위를 IP 레이어에서는 다시 패킷 데이터 단위로 분해 및 조립합니다.
- 패킷의 최대 크기는 1500 byte 정도이다.
- 최대 세그먼트 크기는 패킷의 최대 크기보다 작다.
- 패킷을 전송하기 위해서 다시 프레임 데이터 단위로 분해 및 조립합니다.

## 초창기 웹 서비스 구조
- 프로그램은 UI(화면), 제어체계(로직), 자료구조(데이터) 3가지로 구성되어 있다.
	- HTML은 자료구조에 해당됨
- 3가지 구성요소로 분리하는 이유는 유지보수성 때문이다.
	- 3가지로 분리하면 유지보수성이 극대화됨
- HTTP 초기에 1.0, 1.1을 많이 사용하닥, 2.0 나오고, 지금 3.0(2022년 기준)까지 나왔습니다.
	- 현재까지도 많이 사용하는 것은 1.1 버전
- 웹 설계시 대전제는 HTTP 통신시 TCP/IP 연결을 기반으로 하도록 설계하였음
	- HTTP 프로토콜의 대표적인 특징은 무상태(Stateless)성을 가짐
- TCP/IP 연결에서 상태라는 개념을 포함하는데, 그 위에서 작동하는 HTTP는 상태가 없는 특징을 가짐
- Method GET 특징은 읽기 연산입니다.
- 사용자가 브라우저에 URL을 입력하면 DNS에서 도메인 네임에 대한 IP 주소를 알려줌
- 요청한 HTML 문서를 응답받은 다음에 HTML 문서안에 태그가 존재함.
- 브라우저는 HTML 문서를 가지고 구문 분석(Parsing)을 수행합니다.
	- 이 자료구조가 비선형으로 되어 있습니다.
- 구문 분석을 마치면 브라우저는 화면을 HTML 내용을 렌더링합니다.
- 브라우저를 이루는 핵심 요소는 첫번째는 구문 분석기(Praser), 두번째는 렌더링 엔진이 핵심 요소입니다.
- 이 당시의 브라우저는 문서 뷰어와 같은 역할을 수행함. 기존 문서 뷰어기와 다른점은 원격지의 문서 뷰어입니다.

## 웹 서비스의 3대 요소
- 기존까지의 클라이언트와 서버간에 작용은 클라이언트에서 서버로 정적이 리소스를 요청하고, 서버는 리소스를 응답하는 단방향 작용을 수행하였음.
- 그 이후에 HTMl 문서에 스타일링을 해야하는 요구사항이 생겼음.
	- HTML 문서에 직접적으로 스타일링을 하면 유지보수하기 어려워짐. 왜냐하면 HTML은 자료구조 성격이고, 스타일링은 UI 성격임.
	- HTML 문서에 스타일링하는 부분을 UI로 분리한 것이 **CSS** 파일이다.
- 또한 HTML 문서의 텍스트만이 아닌 이미지 파일또한 필요하게됨
- 최종적으로 클라이언트는 서버에 HTML + CSS + Image 파일을 요청하게 됨
- 서버에는 HTML + CSS +Image 파일들이 HDD에 저장되어 있음
	- 이러한 파일들을 다른 말로 정적(static)인 파일들임
- 다음 요구사항은 **문서의 내용을 갱신해야 하는 요구사항**이 생겼음
	- 클라이언트에서 서버로 데이터가 전달해야 하는 상황이 생김
- 대표적인 예시로 로그인이 존재합니다.
	- 사용자는 ID, PW를 입력하고 서버에 요청하게 됨
	- 서버에 요청시 ID, PW를 같이 전달함
	- 이때 HTTP Method는 POST
- 기존까지의 웹서버는 송수신 담당이었음. 예전에는 이러한 처리까지도 다 담당했었는데, 분리하기 시작했음.
	- 웹의 구성 요소가 추가됨. 이 구성 요소는 로그인과 같은 요청을 처리하게 됨
- 웹서버는 로그인과 같은 요청을 그대로 가져다가 처리 담당 서버에게 위임함.
	- 로그인과 같은 처리가 추가되면서 클라이언트와 서버간에 양방향 작용이 됨
	- 그런데 이러한 양방향 작용이 되면서 상태가 되고, 이러한 상태는 변화가 됨.
	- 그런데 HTTP 프로토콜 특징상 무상태가 원칙임. 그래서 이러한 상태를 어디간에 기억해두어야 함.
	- 이러한 상태 데이터를 어딘가에 저장해야 할 요구사항이 생김. 이러한 문제를 해결하기 위해서 데이터베이스(DB)가 생김
- 자료를 처리하는 서버와 DB는 항상 연결 상태
	- 처리 서버와 DB 연결 방법은 다양함
	- Java 같은 경우에는 JDBC 드라이버가 존재함.
	- SQL을 이용해서 데이터를 조회함.
- 처리 서버에서는 DB에서 조회한 데이터를 찾은 다음에 템플릿 문서에 찾은 데이터를 주입하여 새로운 문서를 생성함.
	- 이러한 문서는 **동적인 문서**가 됨
- 이렇게 생성한 동적인 문서를 클라이언트에게 응답함.
- 그런데 처리 서버가 데이터를 찾지 못하는 경우도 있음. 그럴때는 그에 맞는 동적인 html 문서를 응답할 것이다.
- 여기서 실패했을 경우에 대비하여 동적인 움직임을 추가하고자 하는 요구사항이 생김
	- 브라우저에 SW 연산을 주입하게 됨. 이 엔진을 처음에는 모카(Mocha)라고 부르고, LiveScript로 변경되었다가 마지막에는 **Javascript**라고 부르게 됨.
- **자바스크립트는 브라우저 클라이언트에서 실행됨**
- 정적인 리소스를 응답하는 웹 서버는 최종적으로 HTML + CSS + Image + Javascript 파일까지 응답하게 됨.
- 클라이언트 웹 브라우저를 이루는 3가지 요소
	- 구문 분석기(Praser)
		- DOM Tree 구성
	- 렌더링 엔진
	- Javascript 실행 엔진
- 클라이언트쪽에서는 상태 유지 데이터를 어떻게 구현?
	- 쿠키(Cookie)
		- key + value 형태
		- 속성은 범위, 기간 등의 속성을 가짐

## WAS, JVM 그리고 RESTful API
- 웹 서버(Web Server)와 데이터베이스 사이에서 동적인 문서를 생성하기 위한 처리를 담당하는 서버를 **WAS(Web Application Server)**라고 부름.
- 웹 서버
	- 정적인 리소스를 송수신하기 위한 서버
- 데이터베이스
	- 상태 데이터를 저장하기 위한 서버
- 웹 애플리케이션 서버
	- 동적인 문서를 생성하거나 로직을 처리하기 위한 서버
- WAS의 3가지 요소 (MVC)
	- Model : 데이터를 저장하고 로직을 처리함
	- View: 동적인 문서를 생성함
	- Controller: 클라이언트의 URL 주소를 처리함
- User 모드에다가 CPU를 소프트웨어로 구현함.
	- Java 언어에 대해서만 작동하는 가상 머신을 JVM(Java Virtual Machine)이라고 부르기로 함
	- JVM이 실행될때는 가상 머신이 인식할 수 있는 기계어로 작동하는데, 이를 Java Byte Code라고 부름.
	- 소프트웨어들이 JVM 위에 존재한다면 이 소프트웨어들이 작동하기 좋게 만들기 위해서 중간에 또다른 소프트웨어들을 넣습니다. 이 중간에 위치한 소프트웨어들을 미들웨어(MiddleWare)라고 부름.
	- 이러한 미들웨어 역할을 수행하는 소프트웨어중에 WAS가 있습니다.
		- WAS가 클라이언트와 서버간에 요청 및 응답 처리를 쉽게 해줌
	- WAS를 구현하기 쉽게 하기위해서 그 위에 Framework를 넣습니다. 초바자들은 프레임워크 위에서 WAS를 구현함.
		- 대표적으로 Spring, Spring Boot Framework가 있습니다.
	- 소프트웨어 위에 JSP, PHP, ASP와 같은 것들을 사용할 수 있음.
- 3-Tier Web Service
	- Web Server
	- Web Application Server
	- DB
- 주요 응답 지연이 발생하는 곳은 WAS에서 DB로 데이터를 질의하고 응답하는 사이에 발생함.
- 그리고 WAS에서 비즈니스 로직을 자체 처리할때 시간이 오래 걸려서 응답 지연이 발생할 수 있음.
- 주요 응답속도 지연 발생하는 곳
	- DB 성능 이슈
	- JVM의 처리 속도
- DB와 JVM의 처리 속도를 모니터링하는 시스템이 존재하는데, APM(Application Performance Management)라고 부름.
- APM은 DB와 JVM을 성능을 모니터링함.
	- 대표적으로 스카우터(Scouter) APM이 존재함.
- 웹 브라우저와 웹 서버간에 요청 및 응답시 성능 기준
	- 네트워크 속도 성능
- WAS와 DB 사이에 성능을 높이기 위해서 데이터베이스에 **튜닝**을 수행함.
- 웹 서버는 프론트 엔드 서버라고 하고, WAS 및 데이터베이스 서버를 백엔드 서버라고 부름.

RESTful API
- 최근에는 브라우저에서 웹 서버로 요청(GET, POST 등) 및 응답하는 구조는 동일함.
- 그러나 요즘에는 데이터만 응답함. 주로 JSON 형태의 데이터만 응답합니다.
	- 시간이 지나면서 UI를 생성하는 엔진이 매우 다양해짐
	- 애플, 안드로이드, PC 등 매우 다양함.
	- HTML 문서는 이러한 실행 환경에 매우 예민함.
- 그래서 각각의 실행환경별로 HTML 문서를 준비하는 것이 아닌 데이터만 응답하는 것으로 변경함.
- 웹 브라우저가 JSON 데이터를 응답받으면 스스로 실행환경(애플, 안드로이드, PC 등)에 맞게 HTML 문서를 생성하기로 함.
	- 자바스크립트 엔진을 이용해서 HTML 문서를 스스로 생성함.
	- 여기에 들어가는 프레임워크가 탄생함.
		- 대표적으로 React, Vue.js 등
- 이러한 웹 클라이언트가 웹 서버에게 생성, 읽기, 쓰기(덮어쓰기, 수정), 삭제하는 요청들을 CRUD(Create-Search-Update-Delete)라고 줄여부름.
- 자바스크립트는 이러한 CRUD를 call하기만 하면 됨. 이러한 Call을 RESTful API라고 부름.

보안
- 웹서버와 인터넷이 연결할때 중간에 3가지 요소가 들어감
	- IPS(칩입 방지 시스템)
	- SSL(암호화 처리)
	- WAF(웹 애플리케이션 방화벽)

## LAN과 WAN 구별 방법
- 커널 모드 위로는 소프트웨어이고, Logical합니다.
	- Logical == Virtual
- Interenet은 Logical Network이다. 즉, **Internet은 Virtual Network**이다.
- LAN과 WAN을 구분하는 기준
	- 논리적(Logical)인것이냐 물리적(Physical)인지 판단
- Interenet은 Virtual Network이기 때문에 WAN(World Area Network)
- 하드웨어 부분인 이더넷 부분이 LAN(Local Area Network)
- 이더넷(Ethernet) 레이어의 식별자는 MAC 주소이다. MAC 주소는 48bit로 표현한다.
- LAN은 MAC 주소를 기반으로 작동하는 네트워크라고 생각함.
- WAN은 IP 주소를 기반으로 작동하는 네트워크
- IP 주소, MAC 주소, 특수 주소 존재함
	- 특수 주소 : 방송 주소(Broadcast Address)
	- **방송 주소가 적용되는 범위까지가 LAN이라고 생각함**

정리
- 커널 모드를 포함한 윗단이 소프트웨어이고, 이 소프트웨어들은 Logical합니다.
- Logical하다는 것은 Virtual하다는 것과 같은 의미로 사용 가능함.
- IP 레이어의 Internet은 Logical Network 이므로 즉, Virtual Network라고 말할 수 있다.
- LAN과 WAN을 구분하는 기준은 Logical이냐 Physical이냐로 판단해볼 수 있다.
- Internet은 Virtual Network이기 때문에 WAN으로 판단
- 하드웨어 부분인 이더넷 부분은 물리적이기 때문에 LAN으로 판단
- LAN은 MAC 주소 기반으로 작동하는 네트워크
- WAN은 IP 주소 기반으로 작동하는 네트워크
- 브로드캐스트 주소가 존재하는데 브로드캐스트 주소가 적용되는 범위까지가 LAN 이라고 생각함.

## 패킷의 생성 원리와 캡슐화
패킷의 생성 원리
- 프로세스가 커널 모드의 TCP에 접근하기 위한 인터페이스가 Socket입니다.
	- Socket은 File의 일종
	- 프로세스는 그래서 Socket File에 읽기 또는 쓰기 작업을 수행합니다.
	- 프로세스는 Socket 파일에 **Stream 데이터 단위**로 데이터를 쓰기 작업합니다.
	- Stream 데이터는 최대 길이를 알수 없습니다. 프로세스에 따라서 다르기 때문입니다.
	- Socket에서 TCP 레이어에 전달시 Stream 데이터를 **세그먼트(Segment) 단위**로 분해하고 세그먼트(Segment) 데이터로 조립하는 과정을 수행합니다.
	- **TCP에서 IP 레이어로 전달시 세그먼트 데이터를 패킷 데이터 단위로 분해 및 조립**합니다.
	- 패킷 데이터는 IP에서 Ethernet 레이어로 전달되면 **Frame 데이터 단위**로 분해 및 조립합니다.
- 패킷의 최대 크기 : 1500byte
- 패킷 구성 요소
	- Header
		- IP : L3, 20byte
		- TCP : L4, 20byte
	- Payload
		- 크기: 1460 byte
		- 실질적인 패킷의 크기는 1460 byte
- 패킷 비유 예시
	- 패킷을 택배로 비유할 수 있음.
	- 택배에 붙어있는 운송장을 헤더라고 비유함
	- 택배의 내용물이 payload
- DPI(Deep Packet Inspection)
	- 패킷의 내용물을 분석하는 것
- 세그먼트를 패킷의 내용물로 비유할 수 있는데, 이렇게 패킷 안에 세그먼트 데이터가 포함되어 있는것이 **캡슐화(Encapsulation)**이라고 부름
- Frame 비유
	- 패킷을 담은 Frame을 택배차에 비유할 수 있음
	- 한갸의 택배차에 여러개의 택배가 적재되어 있는 것처럼 하나의 Frame에 여러개의 패킷이 들어있을 수 있음

정리
- 세그먼트: 택배의 내용물
- 패킷 : 택배
- 프레임 : 택배의 차량

## L2 스위치에 대하여
- L2 스위치는 MAC 주소(48bit)를 가지고 스위칭을 하는 기기입니다.

다음 명령어를 실행하여 IP 주소 및 MAC 주소를 확인합니다.
```shell
ifconfig -a
```
실행 결과를 보면 MAC 주소가 `10:b5:88:79:b1:4c`입니다.
![](images/Pasted%20image%2020260309152231.png)

- Network는 Switch의 집합체입니다.
- PC가 존재하고 PC의 NIC를 이용해서 스위치와 연결될 수 있습니다. 이 스위치를 L2 Access Switch라고 부른다.
- 또다른 PC가 해당 L2 스위치에 연결되면 첫번째 PC와 두번째 PC간에 통신이 가능합니다.
- L2 스위치는 또다른 스위치와 연결되는데, 이 스위치를 **L2 Distribution**이라고 합니다.
- L2 Distribution 스위치에 다른 PC 또한 연결이 가능합니다.
- L2 Access 스위치와 L2 Distribution 스위치의 차이점
	- 누구를 위한 스위치이냐에 따라 다름
	- 일반적인 PC는 엔드포인트로써 L2 Access 스위치를 만난다.
	- L2 Distribution 스위치는 Network 자체로서, 스위치를 위한 스위치입니다.
	- L2 Access는 비유로 하면 방(Room) 하나 정도, L2 Distribution은 한층(Floor) 정도
- L2 Distribution 스위치 또한 외부의 기기와 연결이 가능합니다. 보통 게이트웨이(Gateway) 역할을 수행하는 라우터 스위치와 연결합니다.
- Router 스위치는 다시 인터넷과 연결됩니다.
	- Router는 비유로 하면 건물 하나 정도
- 엔드포인트와 직접 만나는 스위치가 L2 Access 스위치
- L2 Access와 연결되는 스위치가 L2 Distribution 스위치
- L2 Distribution 스위치는 Router 스위치와 연결됨
- L2 Access 스위치에서 L2 Distribution 스위치로 연결되는 선을 **업링크(Uplink)**라고 부름
	- Uplink와 Link-Up은 다른 용어의 의미
	- Link-up은 랜 케이블 연결시 녹색불(연결되어 있따는 의미)
	- Link-down은 랜 케이블 비연결시 연결이 끊겼다는 의미

정리
- L2 스위치는 MAC 주소를 이용하여 스위칭한다.
- MAC 주소는 48bit 크기를 가진다.
- 엔드포인트와 직접 만나는 스위치를 L2 Access 스위치라고 한다.
- L2 Access 스위치와 만나는 스위치를 L2 Distribution 스위치라고 한다.
- L2 Distribution 스위치는 마지막에 Router 스위치와 연결된다.
- Router가 PC들의 게이트웨이 역할을 수행함.
- L2 Access 스위치에서 L2 Distribution 스위치로 연결되는 것이 Uplink라고 부른다.
- Uplink와 Link-up과는 다른 개념의 용어이다.
 
### keyword
- Switch
- L2 Access
- L2 Distribution
- Uplink
- Link-up
- Link-down
- Gateway
- Router

## IP 헤더 형식과 의미
IP 헤더 형식
![](images/Pasted%20image%2020260309161206.png)
- 패킷의 헤더에서 TCP 헤더 20byte, IP 헤더 20byte 크기를 가집니다.
- MTU(Maximum Transfer Unit) : 1500 byte
- MSS(Maximum Segment Size) : 1460 byte
- 패킷의 데이터 사이즈는 이론상 최대 65536 byte까지 가능함.
	- 2^16=64kb
- 하지만 2022년 기준 패킷의 MTU는 1500byte이다.
- 패킷의 Total length가 16bit이기 때문에 이론상 패킷의 데이터를 최대 2^16=65536byte를 넣을 수 있는 것입니다.
- IHL(Internet Header Length) : 5
	- 32bit=4byte
	- 헤더의 크기 5 x 4byte = 20bytes
- Identification : 단편화 관련 정보
- TTL(Time to Live)
	- 라우터가 인접한 라우터에게 전달할때마다 TTL이 1씩 감소함
	- TTL의 크기는 8bit이므로 2^8=256(0~255)
	- Router를 255개 지나고 나면 0이 됨
	- TTL이 감소하다가 0이 되면, 해당 Router가 패킷을 버리게 된다.
- Protocol
	- 4계층이 무엇인지 저장하는 헤더
	- 해당 패킷이 TCP인지, UDP 인지 해당 헤더를 통해서 판단 가능함.
- Header Checksum
	- 전송 과정에서 오류가 있는지 확인하는 체크섬 값이 저장됨
- Source Address
	- 출발지 IP 주소
- Destination Address
	- 목적지 IP 주소

## Router의 내부 구조와 Inline
Router 장치는 L3 Switch 중 하나인 기기입니다. L3 Swtich 기기가 작동한다는 것은 스위칭(Switching) 처리를 패킷(Packet) 단위로 처리하겠다는 의미입니다.

다음 그림을 보면 L2 Access Switch는 PC가 가장 처음 네트워크 연결되는 입구입니다. 이러한 L2 Access Switch들이 연결되는 기기가 L2 Distribution Switch입니다. L2 Distribution Switch는 여러개의 L2 Access Switch를 모아서 Router에게 전달하는 네트워크 기기입니다.
- L2 Access Switch는 공유기 같은 기기에 내장되어 있는 경우가 많습니다.
![](images/Pasted%20image%2020260321133327.png)

L2 Distribution Switch는 네트워크를 모아서 Router에게 전달하는데, 이러한 Router의 네트워크 인터페이스(NIC)는 적어도 최소 2개를 가지고 있습니다. Router는 그 이후 네트워크 요청을 인터넷(Internet)으로 전달하게 되는 구조입니다. 그리고 인터넷을 거쳐서 어느 Router에 도달하게 되고, 그 Router는 네이버와 같은 서버에 도달하게 됩니다.
- 위 그림에서는 인터넷으로 추상화하였지만 인터넷 또한 거대한 Router의 집합체입니다.

Router 기기 또한 하나의 호스트(Host)이기 때문에 하나의 컴퓨터입니다. Router 기기는 최소 2개의 **네트워크 인터페이스 카드(Network Interface Card, NIC)** 를 가지고 있습니다. 하나의 NIC는 네트워크 요청을 내부로 받는 용도이고, 다른 하나의 NIC는 외부로 전달하기 위한 용도입니다.
Router 기기 또한 운영체제를 갖고 있기 때문에 커널 모드에 TCP, IP가 존재합니다. 그리고 유저 모드에서는 여러개의 프로세스(Process)가 수행되고 있습니다.
Router의 내부 NIC로 네트워크 패킷이 들어오면 NIC를 거쳐서 커널 모드의 IP -> TCP를 거치고 유저 모드의 프로세스에 도달하여 네트워크 처리를 할 수 있습니다. 프로세스에서 네트워크 처리를 마치면 다시 TCP->IP->외부 NIC를 거쳐서 외부로 빠져나갑니다.
그런데 네트워크 전송 과정에서 하드웨어 -> 커널 모드 또는 커널 모드 -> 유저 모드로 건널때마다 네트워크 비용(CPU, wait time 등)이 많이 듭니다.

제일 좋은 방법은 커널모드의 IP, TCP를 거치지 않고, 내부 NIC에서 외부 NIC로 바로 직접 가는것이 좋은 방법입니다. 기본적으로 Router의 네트워크 처리는 프로세스 또는 IP 수준 또는 NIC에서 처리될 수 있습니다. 위에서 설명하듯이 하드웨어 수준의 NIC 수준에서 네트워크 처리(Swithing)하는 것이 제일 빠릅니다.

Router가 Switch라고 불리는 이유는 내부 NIC로 패킷이 왔고, 바로 외부 NIC로 단순 전송하지 않기 때문입니다. 왜냐하면 Router에 2개의 NIC만 존재하는 것이 아니라 추가적인 외부 NIC가 존재할 수 있기 때문입니다. 예를 들어 패킷이 내부 NIC에 도착하고 패킷을 IP 수준에서 네트워크 처리합니다. 그리고 IP 수준에서 외부 NIC #2 로 전송할지 외부 NIC #3 으로 전송할지 선택해야 합니다. 이것을 네트워크 인터페이스 선택이라고 부릅니다.

![](images/Pasted%20image%2020260321134858.png)

네트워크로 프레임(Frame) 단위 데이터가 들어와서 패킷(Packet) 단위로 분해 및 조립하는 것은 IP 수준에서 보면 데이터를 읽기(Read)한다는 것입니다. 그리고 IP가 네트워킹 처리하고 두 NIC 중 하나를 선택하여 쓰기(Write) 작업을 수행합니다.
그런데 만약 IP가 읽기 작업은 하지만, 쓰기 작업을 하지 않는 상황이 발생하면 해당 선택을 **DROP**이라고 부릅니다. DROP 선택을 하게 되면 외부 NIC로 나가지 않게됩니다. 이러한 행위 **필터링(Filtering)**했다고 부릅니다.

IP에서 쓰기 작업을 할지 선택하는 기준은 IP 주소입니다. 그런데 2개의 NIC 중에서 적정한 것이 없다면 DROP 선택을 하게 됩니다. 
인라인(Inline) 장비는 Bypass 또는 DROP 선택을 하게 됩니다. 만약 네트워킹 처리만 한다면 이를 Router라고 부르고, 보안적인 이유로 필터링(Bypass or DROP)을 수행한다면 방화벽이라고 부를수 있습니다. 이러한 방화벽을 패킷 필터링 방화벽이라고 부릅니다. Router와 패킷 필터링 방확벽은 구조가 거의 비슷합니다.

인라인(Inline) 장비를 정리하면 패킷 단위로 네트워킹을 처리하는 장치이고 네트워크를 대상으로 Bypass 또는 DROP 선택을 할수 있습니다. Bypass를 선택하게 되면 외부 NIC를 통해서 외부로 나가게 됩니다. 만약 인라인 장치에서 보안적인 이유로 의사결정하면 방화벽이라 부를 수 있습니다. 방화벽은 패킷 단위로 필터링을 수행하게 됩니다. 그래소 방화벽을 패킷 단위 필터링이라 부릅니다.

정리
Router와 방화벽은 L3 스위치에 속하고 IP 주소를 이용하여 통신합니다. 이때 Router는 Bypass 또는 Drop을 선택하게 됩니다. 이러한 두 선택 과정을 인라인(Inline) 처리라고 합니다. Router는 전송시 NIC, IP, Process 수준중 하나에서 네트워킹 처리할 수 있습니다. NIC와 같은 저수준에서 처리할 수록 처리속도가 빠릅니다.
방화벽 기기도 L3 스위치에 해당하는데 보안적인 이유로 Bypass 또는 Drop 선택을 합니다. 기본적인 구조는 Router와 방화벽 모두 구조가 비슷합니다. 하지만 판단 기준은 라우팅 용도인가 보안용인가로 기준을 삼는다.

## Inline 구조와 Out of path 구조
